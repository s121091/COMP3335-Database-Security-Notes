⚠️ 典型警告 1：USER.DEFPWD (Severe Risk)
發現未鎖定賬戶使用默認密碼（如 SCOTT, SYSTEM）。
必考避坑：連已經 Locked（鎖定）的賬戶也必須修改默認密碼！防止日後解鎖瞬間成為後門。
⚠️ 典型警告 2：PRIV.DBA (Evaluate)
DBA 角色權限過大，應遵循 Least Privilege (最小權限) 與 SoD (職責分離)，使用獨立實名賬號，避免授予 WITH ADMIN OPTION。

定位：Stand-alone command line tool (獨立命令行工具)。注意它不僅查 DB 內部，還查網絡層 (Listener) 與 操作系統層 (OS File permissions)！

歸屬維度 Rule 規則代碼 檢查內容摘要 (Summary) 速記提示
賬戶與角色 USER.EXPIRED 過去 30 天未改密碼的用戶（排查幽靈賬戶 Ghost accounts?） USER = 賬戶狀態

特權角色 PRIV.DBA 誰擁有最高權限的 DBA 角色？ 排查超級管理員濫用
授權控制 AUTH.DV 是否部署了防內鬼 (insider threats)、憑證被盜與人為失誤的控制？ DV = Database Vault

Pillar 2: Prevent

數據脫敏 (Masking vs. Redaction) 與細粒度訪問控制 (VPD) (Pages 12–23)

⚖️ 必考核心對比：Data Masking (靜態脫敏) vs. Oracle Data Redaction (動態編校) Pages 13–19

對比維度 1. Data Masking (靜態數據脫敏 - Pages 13–14) 2. Oracle Data Redaction (動態數據編校 - Pages 15–19)
本質機制 Static Masking (靜態脫敏) Dynamic Masking (動態脫敏，On-the-fly 實時處理)
是否改變底層存儲數據？ YES！Permanently altering data (永久改變數據)，脫敏後不可逆。 NO！Does NOT change stored data value，只改變返回給應用程序的 SQL 查詢結果顯示。
適用環境 Non-production (非生產環境)：如開發 (DEV)、測試 (TEST)、分析、外包給第三方廠商。 Production (生產環境)：如呼叫中心 (Call Center) 屏幕向客服人員展示客戶資料。
防範對象 黑客，以及開發人員、測試人員、IT 管理員、外包人員。 終端應用用戶 (Application End Users，限制敏感數據暴露)。
核心算法 / 轉換策略 5 種脫敏算法 (Page 14)：
• Fictitious Data：末尾打井號 613-30-####
• Random Data：替換為隨機姓名 (Jim Arthur)
• Date Aging：日期統一偏移 (減 4 年 2 個月)
• Numeric Alteration：數值增減 (+200)
• Shuffling Data：同列數據洗牌互換 		4 種編校策略 (Pages 17–18)：
• Full redaction：字符變單空格 ' '、數字變 0、日期變 01-JAN-01
• Partial redaction：部分打星號，如 XXX-XX-4328
• Regular expressions：正則匹配格式（如脫敏 Email）
• Random redaction：每次查詢返回隨機生成的值
🔐 Page 19 重點：Combining TDE with Data Redaction（雙劍合璧）
• Data Redaction 保護「應用顯示層」（SQL 查詢結果動態打碼，防終端用戶偷看）。
• TDE (Transparent Data Encryption 透明數據加密) 保護「物理存儲層」（Disk 磁盤、Backups 備份、Exports 導出文件、Off-Site 異地存儲全部加密，防硬盤或備份被盜）。

👤 數據庫訪問控制原則与 Named UsersPages 20–22

  • Named Users (實名獨立賬戶)：嚴禁管理員為了方便共用賬戶或直接使用 SYSTEM！共用賬戶會徹底喪失 Accountability (可追責性)。每個 DBA 必須有獨立實名賬戶。
  • Separation of Duties (SoD 職責分離) & Principle of Least Privilege (最小權限原則)。
  • Granularity of Access Rights (訪問粒度 - Page 22)：權限粒度可控制在整個 DB $\rightarrow$ 單張 Table $\rightarrow$ 特定 Rows (行) 或 Columns (列)（例如：Nancy 只能看自己的記錄和下屬的記錄）。

🎯 Virtual Private Database (VPD 虛擬專用數據庫)Page 23 (高頻考點)

支持在行級 (Row-Level Security, RLS) 與列級 (Column) 實現細粒度訪問控制 (FGAC)。

-- 用戶原本發出的查詢：
SELECT * FROM employees;

-- VPD 策略在底層自動動態拼接 WHERE 子句 (Adds a dynamic WHERE clause)：
SELECT * FROM employees WHERE account_mgr_id = 148;

🔑 權限要求：用戶必須被授予 DBMS_RLS PL/SQL 包的 EXECUTE 權限，才能創建 Oracle VPD 策略。

💻 Oracle DB 審計實操 SQL 命令Page 26 (必背語法)

使用 AUDIT 語句開啟審計，可指定 WHENEVER SUCCESSFUL 或 WHENEVER NOT SUCCESSFUL：

-- 1. 僅在成功創建用戶時記錄審計
SQL> AUDIT CREATE USER WHENEVER SUCCESSFUL;

-- 2. 無論成功或失敗，只要刪表就記錄
SQL> AUDIT DELETE TABLE;

-- 3. 僅在登錄失敗時記錄（用於檢測密碼暴力破解！）
SQL> AUDIT CREATE SESSION WHENEVER NOT SUCCESSFUL;

-- 4. 查詢審計日誌視圖（按時間倒序）
SQL> SELECT * FROM dba_audit_trail ORDER BY timestamp DESC;

🏰 Oracle Audit Vault and Database Firewall (AVDF)Page 27

  • 集中存儲與防內鬼篡改：將各個數據庫與操作系統的審計數據轉發到遠程集中位置 (remote centralized location)，防止被審計的特權管理員自己偷偷修改或刪除日誌 (secure from tampering)！
  • Database Firewall (數據庫防火牆)：在網絡層實時監控 SQL 流量（放行綠色 ✓、告警黃色 !、攔截紅色 ✕）。
